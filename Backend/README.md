# واجهة برمجة التطبيقات (Backend API) - تطبيق إدارة جمعية تحفيظ القرآن الكريم

واجهة برمجة تطبيقات متكاملة ومبنية بلغة **TypeScript** و **Node.js** و **Express** وفقاً لدفتر الشروط (CDC الإصدار 1.2).

---

## 🌟 الميزات المنجزة وتوافقها مع دفتر الشروط

| المعرف | الميزة في دفتر الشروط | الحالة | الوصف |
| :--- | :--- | :---: | :--- |
| **F1** | إدارة الأشخاص (Persons) | ✅ مكتملة | جدول موحد لجميع الأشخاص مع نوع الشخص (`student` / `sheikh` / `both`) والتحقق من وجود وسيلة اتصال (هاتف أو بريد). |
| **F2** | إدارة المقرات (Branches) | ✅ مكتملة | إضافة وتعديل وعرض المقرات (المقرات الـ 4 الحالية وقابلة للتوسع). |
| **F3** | إدارة الحلقات (Halaqat) | ✅ مكتملة | ربط كل حلقة بمقر واحد وتحديد اسمها ومستواها. |
| **F4** | ربط الشيخ بالحلقات | ✅ مكتملة | إمكانية إشراف الشيخ على عدد غير محدود من الحلقات في نفس المقر أو عبر مقرات مختلفة. |
| **F5** | ربط الطالب بالحلقات | ✅ مكتملة | تسجيل الطالب في حلقة أو أكثر ومتابعة انتسابه. |
| **F6** | الأدوار الإدارية (Roles) | ✅ مكتملة | الأدوار المركزية (المال، التنظيم، رئيس الشعبة، الإعلام، الشباب، الأحداث، الإدارة) وأدوار المقرات. |
| **F7** | ربط الشخص بالدور | ✅ مكتملة | ربط الشخص بأكثر من دور مركزي أو خاص بمقر محدد. |
| **F8** | مسؤولو المقر (الحد الأقصى = 3) | ✅ مكتملة | تعيين 2 أو 3 مسؤولين لكل مقر مع تحقق صارم في قاعدة البيانات والـ API يمنع تجاوز 3 مسؤولين. |
| **F9** | إضافة الطلاب | ✅ مكتملة | إضافة الطلاب من قِبل المسؤول المركزي، أو مسؤول المقر (لمقره)، أو الشيخ (لحلقاته). |
| **F10** | البحث المتقدم عن الطلاب | ✅ مكتملة | فلترة الطلاب بعوامل متعددة ومجتمعة (المدرسة، المستوى، المقر، الحلقة، الشيخ، الاسم، الجنس، الفئة العمرية، تاريخ التسجيل). |
| **F11** | تصدير نتائج البحث | ✅ مكتملة | تصدير نتائج البحث فورياً بصيغ **Excel (.xlsx)** و **CSV** (مع UTF-8 BOM) و **PDF**. |
| **F12** | الإشعارات التلقائية | ✅ مكتملة | إشعار تلقائي للشيخ عند إضافة طالب جديد إلى إحدى حلقاته، مع إدارة الإشعارات والمقروء منها. |
| **F13** | الصلاحيات ونطاق الرؤية (RBAC) | ✅ مكتملة | المسؤول المركزي يرى ويبحث في الكل؛ مسؤول المقر مقيد بمقره؛ الشيخ مقيد بحلقاته. |
| **S1** | لوحة تحكم إدارية (Dashboard) | ✅ مكتملة | إحصائيات فورية، نسب توزيع الطلاب حسب المقر وحسب المستوى الدراسي، وسجل الحركة الأخيرة. |
| **S2** | تقارير إدارية قابلة للتصدير | ✅ مكتملة | تقارير متخصصة وقابلة للتصدير (PDF / CSV / Excel). |
| **N1** | إشعارات متقدمة | ✅ مكتملة | إرسال إشعارات جماعية وبث إداري (Broadcast). |
| **N2** | سجل النشاطات (Audit Logs) | ✅ مكتملة | تسجيل العمليات الإدارية، من أضاف/عدّل، والقيم السابقة والجديدة مع الوقت. |

## 🗄️ دعم قواعد البيانات المزدوج (Dual Database Support)

يعمل النظام بسلاسة في وضعين دون الحاجة لتغيير أي كود:

1. **الوضع التلقائي (SQLite - Zero Config):**
   - يستخدم محرك `node:sqlite` المدمج في Node.js 24.
   - لا يتطلب تثبيت أي برامج أو خوادم خارجية.
   - يتم إنشاء قاعدة البيانات فورياً وتعبئتها بالبيانات التجريبية في: `Backend/data/quran_association.db`.

2. **وضع الإنتاج (PostgreSQL 14+):**
   - يدعم الاتصال المباشر بخادم PostgreSQL وفقاً لمخطط `database/schema.sql`.
   - يتم التبديل تلقائياً بمجرد تحديد متغير `DATABASE_URL` في ملف `.env`:
     ```env
     DATABASE_URL=postgresql://postgres:password@localhost:5432/djam3iya
     ```

## 🚀 التشغيل والبدء السريع

### 1. تثبيت الحزم (تم مسبقاً)
```bash
cd Backend
npm install
```

### 2. تهيئة وتعبئة قاعدة البيانات (اختياري، يتم تلقائياً عند التشغيل)
```bash
npm run seed
```

### 3. تشغيل خادم التطوير مع المراقبة الحية (Watch Mode)
```bash
npm run dev
```
سيعمل الخادم على: `http://localhost:5000`

### 4. بناء وتشغيل نسخة الإنتاج
```bash
npm run build
npm start
```

### 5. تشغيل اختبارات التحقق الشاملة (32 اختباراً)
```bash
npm test
```

## 📡 دليل نقاط النهاية للـ API (Endpoints Reference)

### 1. المصادقة والجلسات (`/api/auth`)
- `POST /api/auth/login`: تسجيل الدخول وإرجاع رمز JWT والصلاحيات.
- `GET /api/auth/me`: بيانات الحساب الحالي والصلاحيات ونطاق العمل.
- `POST /api/auth/logout`: تسجيل الخروج.

### 2. إدارة الأشخاص (`/api/persons`) — F1
- `GET /api/persons`: جلب قائمة الأشخاص (مع فلاتر النوع، الاسم، الهاتف، الجنس).
- `GET /api/persons/:id`: الملف الكامل للشخص وعلاقاته بالحلقات والأدوار.
- `POST /api/persons`: إضافة شخص جديد (يشترط هاتف أو بريد إلكتروني).
- `PUT /api/persons/:id`: تعديل بيانات الشخص.
- `DELETE /api/persons/:id`: حذف الشخص.

### 3. المقرات ومسؤولو الفروع (`/api/branches`) — F2, F8
- `GET /api/branches`: قائمة المقرات مع إحصائيات الطلاب والحلقات والمسؤولين.
- `GET /api/branches/:id`: تفاصيل مقر محدد.
- `POST /api/branches`: إضافة مقر جديد (للمسؤول المركزي فقط).
- `PUT /api/branches/:id`: تعديل مقر.
- `DELETE /api/branches/:id`: حذف مقر (إذا خلا من الطلاب).
- `POST /api/branches/:id/admins`: تعيين مسؤول للمقر (**تحقق صارم: بحد أقصى 3 مسؤولين**).
- `DELETE /api/branches/:id/admins/:personId`: إزالة مسؤول من المقر.

### 4. الحلقات القرآنية (`/api/halaqat`) — F3, F4, F5
- `GET /api/halaqat`: قائمة الحلقات (مقيدة تلقائياً بنطاق صلاحيات المستخدم).
- `GET /api/halaqat/:id`: تفاصيل الحلقة والطلاب المسجلين والشيوخ المشرفين.
- `POST /api/halaqat`: إنشاء حلقة جديدة.
- `PUT /api/halaqat/:id`: تعديل حلقة.
- `DELETE /api/halaqat/:id`: حذف حلقة.
- `POST /api/halaqat/:id/teachers`: تعيين شيخ للحلقة (F4).
- `DELETE /api/halaqat/:id/teachers/:personId`: إزالة شيخ من الحلقة.
- `POST /api/halaqat/:id/students`: تسجيل طالب بالحلقة (F5) وإرسال إشعار للشيخ (F12).
- `DELETE /api/halaqat/:id/students/:personId`: إلغاء تسجيل طالب.

### 5. الشيوخ المعلمون (`/api/sheikhs`) — F4
- `GET /api/sheikhs`: قائمة المشايخ مع عدد الحلقات والمقرات وإجمالي الطلاب المشرف عليهم.
- `GET /api/sheikhs/:id`: الملف التفصيلي للشيخ وحلقاته وطلابه.
- `POST /api/sheikhs`: إضافة شيخ وتعيينه لحلقات.

### 6. الطلاب والبحث المتقدم والتصدير (`/api/students`) — F9, F10, F11, F13
- `GET /api/students`: البحث المتقدم متعدد المعايير:
  - `name`: بحث جزئي باسم الطالب
  - `school`: بحث باسم المدرسة
  - `level`: ابتدائي، متوسط، ثانوي، جامعي
  - `branch`: اسم أو معرف المقر
  - `halaqa`: اسم أو معرف الحلقة
  - `sheikh`: اسم أو معرف الشيخ
  - `gender`: ذكر / أنثى
  - `date_from` & `date_to`: نطاق تاريخ التسجيل
  - `min_age` & `max_age`: الفئة العمرية
  - *يطبق تلقائياً قيود النطاق بحسب دور المستخدم (F13)*
- `GET /api/students/:id`: ملف الطالب.
- `POST /api/students`: تسجيل طالب جديد (F9) وإرسال إشعار للشيخ (F12).
- `PUT /api/students/:id`: تعديل بيانات الطالب.
- `DELETE /api/students/:id`: حذف الطالب.
- `GET /api/students/export`: تصدير نتائج البحث بصيغ:
  - `format=xlsx` (ملف Excel جاهز)
  - `format=csv` (ملف CSV بترميز UTF-8 مع BOM لقراءة الأحرف العربية)
  - `format=pdf` (مستند PDF منظم بجداول)

### 7. الأدوار والهرم الإداري (`/api/roles`) — F6, F7
- `GET /api/roles`: قائمة الأدوار (المركزية والفرعية) مع عدد المستخدمين.
- `GET /api/roles/:id`: تفاصيل الدور والمنسوبين إليه.
- `POST /api/roles/assign`: تعيين دور لشخص (مركزي أو لمقر).
- `POST /api/roles/unassign`: سحب دور من شخص.

### 8. حسابات المستخدمين (`/api/users`)
- `GET /api/users`: قائمة الحسابات مع الأدوار وآخر نشاط والحالة.
- `POST /api/users`: إنشاء حساب مستخدم لشخص.
- `PUT /api/users/:id`: تعديل الحساب أو تغيير كلمة المرور.
- `DELETE /api/users/:id`: تعطيل أو حذف الحساب.

### 9. الإشعارات (`/api/notifications`) — F12, N1
- `GET /api/notifications`: قائمة إشعارات المستخدم الحالي.
- `GET /api/notifications/unread-count`: عدد الإشعارات غير المقروءة.
- `PUT /api/notifications/:id/read`: تحديد إشعار كمقروء.
- `PUT /api/notifications/read-all`: تحديد الكل كمقروء.
- `POST /api/notifications/broadcast`: إرسال إشعار جماعي لجميع المستخدمين.

### 10. لوحة التحكم والإحصائيات (`/api/dashboard`) — S1
- `GET /api/dashboard/stats`: إحصائيات متكاملة للطلاب، الشيوخ، الحلقات، المقرات، ونسب التوزيع.

### 11. التقارير الإدارية (`/api/reports`) — S2
- `GET /api/reports/students-by-branch`: الطلاب حسب المقر.
- `GET /api/reports/students-by-level`: الطلاب حسب المستوى الدراسي.
- `GET /api/reports/students-by-halaqa`: الطلاب حسب الحلقة.
- `GET /api/reports/students-by-sheikh`: الطلاب حسب الشيخ.
- `GET /api/reports/enrollment-trends`: إحصائيات التسجيل الزمني.
- `GET /api/reports/export`: تصدير أي تقرير بصيغ (PDF / CSV / Excel).

### 12. سجل النشاطات (`/api/audit`) — N2
- `GET /api/audit`: استعراض التغييرات الإدارية السابقة ومن قام بها والقيم القديمة والجديدة.
